Neon Rush Dev Log

This page is a running record of how Neon Rush was made and where it is going. We share it because players often ask how a browser game like this is built, and because writing down decisions helps us improve.

Why a browser game?

We wanted anyone to be able to play within a few seconds, on almost any device, without installing anything. A web game removes every barrier: you open a link and run. It also means we can ship improvements instantly, because the next time you load the page you are playing the latest version.

Technology choices

The game is written in JavaScript. Phaser 3 provides the game loop, physics-style movement and rendering. React builds the interface around it, including the main menu, the heads-up display, the pause screen, the settings panel and the end-of-run results. Vite bundles everything and the site is deployed on Vercel. We chose this stack because it is fast to develop with and produces a small, fast-loading result.

Sound without files

Instead of loading audio files, the game generates its sound effects in the browser using the Web Audio system. This keeps the download small and lets the effects start instantly. Sound can be switched off in Settings.

Saving progress without a server

Neon Rush has no backend. Your best score, total coins and settings are stored in your browser's local storage. The advantage is privacy and simplicity: we never see your data. The trade-off is that progress does not follow you to another device or survive clearing your browser data.

Design decisions

  • One-hit runs keep every attempt short and tense.
  • Automatic running reduces controls to jump and slide, which works on keyboards and touch screens alike.
  • Coin arcs double as visual hints for where to jump.
  • Gradual speed-up from 340 to 720 pixels per second keeps the first seconds friendly and the later seconds exciting.

Known limitations

The game currently has no moving obstacles and no background music, and it is designed for landscape orientation, so phones held upright are not yet well supported.

Roadmap

  1. A layout that works well in portrait on phones.
  2. Moving obstacles for a new kind of timing challenge.
  3. Optional background music with its own volume control.
  4. More written guides based on player questions.
